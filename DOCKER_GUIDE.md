# 🐳 BS-Commerce: Docker Setup & Execution Guide

This guide explains how to run **BS-Commerce** entirely inside **Docker** using Docker Compose.

---

## 📌 Quick Summary

Running the project with Docker manages three core services automatically:
1. **`postgres`** (PostgreSQL 16 on port `5432`)
2. **`redis`** (Redis 7 on port `6379`)
3. **`backend`** (Next.js 15 + Payload CMS 3 app on port `3000`)

---

## 🚀 1. One-Step Quick Start

From the project root:

```bash
# 1. Start all containers in the background (Postgres, Redis, and Backend)
docker compose up -d

# 2. View live logs from the backend service
docker compose logs -f backend
```

Once running, access:
- **Payload Admin Panel:** [http://localhost:3000/admin](http://localhost:3000/admin)
- **API Base:** [http://localhost:3000/api](http://localhost:3000/api)
- **Swagger Documentation:** [http://localhost:3000/docs](http://localhost:3000/docs)
- **GraphQL Endpoint:** [http://localhost:3000/api/graphql](http://localhost:3000/api/graphql)

## 🗄️ 3. Database Migrations & Seeding in Docker

### Running Migrations
Database migrations execute automatically when the `backend` container starts. If you need to run them manually:
```bash
docker compose exec backend yarn db:migrate
```

### Seeding Demo Data
To populate sample categories, products, and store settings inside Docker:

```bash
# 1. Seed storefront configurations (header, footer, basic pages)
docker compose exec backend yarn seed:storefront-config

# 2. Seed Farm Greens catalog (categories, products, variants, stock)
docker compose exec backend yarn seed:farm-greens

# 3. (Optional) Reset/create a local admin user password
docker compose exec -e RESET_ADMIN_EMAIL=admin@example.com -e RESET_ADMIN_PASSWORD=Password123! backend yarn reset:local-admin-password
```

## 🛠️ 4. Useful Docker Commands

| Action | Command |
| :--- | :--- |
| **Start all containers** | `docker compose up -d` |
| **Rebuild & start containers** | `docker compose up -d --build` |
| **View real-time logs** | `docker compose logs -f` |
| **View backend logs only** | `docker compose logs -f backend` |
| **Stop containers** | `docker compose stop` |
| **Stop and remove containers** | `docker compose down` |
| **Stop and wipe database volumes (clean slate)** | `docker compose down -v` |
| **Open a shell inside the backend container** | `docker compose exec backend sh` |
| **Check container statuses & health** | `docker compose ps` |

## 💡 5. Troubleshooting

### Container Health Checks Failing
Run:
```bash
docker compose ps
```
Ensure `postgres` and `redis` show `(healthy)`. The `backend` container waits for both before starting.

### Port Conflicts
If you have local PostgreSQL or Redis running natively on your Mac on ports `5432` or `6379`:
1. Stop native services:
   ```bash
   brew services stop postgresql@16 redis
   ```
2. Or change port mappings in `docker-compose.yml` (e.g. `"5434:5432"`).
